# M6 Android Auto: verification

## Decisions
- **Car App Library 1.7.0** (latest stable on Google Maven; 1.8.0 is only rc). Min car API 5 (`AppManager.showAlert`).
- **Categories:** `fullMap` declares `androidx.car.app.category.NAVIGATION` (own map surface; sideload only, since Play
  restricts it to turn-by-turn apps). `play` declares `androidx.car.app.category.IOT` (status app, template-only).
- **Map surface API (checked in the MapLibre 13.7.1 AAR):** there is no way to render into an external Surface; the
  renderers (`MapLibreSurfaceView`, `MapLibreVulkanSurfaceView`) are bound to a `MapView`. So `fullMap` uses a
  `MapSnapshotter` loop, one snapshot per 500 ms at most (2 fps), pixel ratio 2. Towers, the user arrow, the per-SIM tower
  lines (solid SIM 1, dashed SIM 2, `NetworkColors`) and the signal panel are painted on the surface canvas over the
  latest snapshot, using the camera that snapshot was rendered with. Coverage is injected into the style JSON
  (raster-dem + colour-relief, the legend stops) and goes through the same `MapHttp`/`CoverageInterceptor`.
- **CA:** `RadioState.ca` (`ServiceState.cellBandwidths`: count, kHz list, total) and `RadioState.displayLabel`
  (LTE / LTE-A / 5G / 5G+ from `TelephonyDisplayInfo`, tech and CA count). Secondary-cell bands are not available to
  normal apps, so the text is "CA x3 - 60 MHz". Only the selected SIM sees `TelephonyDisplayInfo`; the other SIM's label
  comes from its tech and CA count.
- **Alerts:** car `Alert` (toast below car API 5). Speech is the existing trip-service TextToSpeech (navigation-guidance
  audio usage, which Android Auto routes to the car speakers); the car module adds no second voice.
- **Auto trip:** `CarConnection.type == PROJECTION` starts it, disconnect stops it unless started by hand or already
  running (`AutoTripPolicy`).
- **Theme:** `carColorPrimary/Secondary` (+ `Dark`) in `CarAppTheme`; the map surface uses `isDarkMode` with the dark
  style and a car-contrast tonal palette. Dynamic wallpaper colour is not available in the car.

## Wiring in :app (minimal)
- Flavours `fullMap` and `play` in `:app` and `:car` (APKs are now `app-fullMap-debug.apk` / `app-play-debug.apk`,
  Gradle test tasks `testFullMapDebugUnitTest` / `testPlayDebugUnitTest`).
- `AppContainer` installs `CarRuntime.source = CarBridge(...)` (new `app/car/CarBridge.kt`). The car has its own
  `DeviceLocationSource` and `ConnectedController` (radio ref-counted as `car`), so the phone's map screen is unaffected.
  Nothing starts until the car UI is visible (`setActive`).
- Turning coverage on in the car selects the connected network's coverage if none is selected, and clears it again
  when the car UI stops (only if it is still the selection the car set).

## Results
- `./gradlew test testDebugUnitTest :app:assembleDebug` passes: both flavours assemble.
- New tests: `CarrierAggregationTest` (CA mapping, labels), `PanelTextTest`, `SignalPaneModelTest`, `AutoTripPolicyTest`,
  `SignalScreenTest` (`TestCarContext`: PaneTemplate rows and the trip action), and for `fullMap` `CarCameraTest` and
  `MapStyleTest`.

## Not verified
- **DHU smoke not run.** `extras;google;auto` installed quickly, but the DHU needs a phone or emulator with the Android
  Auto app and its head-unit server (the local `google_apis` image has neither Play Store nor Android Auto), and none was
  running. So the snapshot loop's frame rate, the canvas drawing, the action strip layout and the car alert have not
  been seen on a head unit. Try: enable Android Auto developer mode, start the head unit server, `adb forward
  tcp:5277 tcp:5277`, run `desktop-head-unit`, install the `fullMap` debug APK (debug builds allow any host).
- `ServiceState.cellBandwidths` content depends on the modem; some devices report an empty array (no CA text shown).
